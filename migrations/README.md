# סכימת מסד הנתונים — סדר הרצה (לכל מופע חדש)

התיקייה הזו מכילה את מבנה מסד הנתונים. מריצים ב-SQL Editor של פרויקט
Supabase החדש **לפי הסדר**:

## 1. סכימת בסיס (החלק הגדול)
המבנה המלא (34 טבלאות, טיפוסים, אינדקסים, טריגרים, RLS ומדיניות) לא נשמר
כקובץ סטטי כי הוא נוצר אוטומטית ממופע חי. כדי להפיק אותו:

1. פותחים את **מופע הייחוס** (למשל אמצעש) ב-Supabase → SQL Editor.
2. מריצים את `001_export_base_schema_FROM_reference.sql`. הוא מחזיר תא אחד
   בשם `full_ddl` שמכיל את כל ה-DDL.
3. מעתיקים את תוכן התא במלואו.
4. עוברים לפרויקט **החדש** → SQL Editor → מדביקים → **Run** (אם מופיעה
   אזהרת RLS, בוחרים **Run without RLS** — המדיניות כלולה ב-DDL עצמו).

> הפרדנו את זה כי ה-DDL נוצר דינמית וגדול; שמירת עותק סטטי הייתה מתיישנת.
> ההפקה-מחדש תמיד תואמת את מבנה מופע הייחוס העדכני.

## 2. אחסון קבצים
מריצים `002_storage_buckets.sql` (יוצר את הבאקטים `ad-files` ו-`issues-archive`
והרשאות). זהה לכל מופע.

## 3. שדרוגים אינקרמנטליים
`2026-07_graphics-proof.sql` וכל קובץ עתידי — לפי תאריך.

## 4. משתמש-על ראשון
אחרי שנרשם המשתמש הראשון דרך האתר, מגדירים אותו כמנהל:
`update public.profiles set role='admin', active=true where id = (select id from auth.users order by created_at limit 1);`
